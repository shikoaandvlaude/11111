
  HRConvert2 Shell Glob Injection PoC
  Vulnerability: CWE-78 / CWE-155 (Wildcard/Glob Injection)
  Affected: HRConvert2 <= 3.4.7
  Author: cenyuhan0324


SUMMARY:
  The ? character passes through sanitizeString() in strict mode.
  When used in shell_exec() without quoting, bash glob-expands it,
  causing commands to process unintended files.

PREREQUISITES:
  - Linux/macOS/WSL with PHP installed (php-cli)
  - No HRConvert2 installation needed

==============================================================
TECHNICAL EXPLANATION
==============================================================

WHY IT WORKS:

  1. sanitizeString() blacklists these characters:
     | \ ~ # [ ] ( ) { } ; : $ ! ^ & % @ > * < " ' / `
     
     Notice: ? is NOT in this list. * is filtered but ? is not.

  2. PHP file_exists() does NOT perform glob expansion.
     So a file literally named "file?.txt" passes the existence check.

  3. Bash DOES perform glob expansion on unquoted arguments.
     ? matches any single character.
     So file?.txt matches: fileA.txt, fileB.txt, fileC.txt, file?.txt

  4. HRConvert2 passes filenames to shell_exec() without escapeshellarg():
     shell_exec('convert '.$pathname.' '.$newPathname)
     
     The variable is inserted directly into the shell string without quoting,
     so bash glob expansion occurs before the command executes.

AFFECTED SHELL_EXEC CALLS (convertCore.php):

  Line 644:  clamscan -r $path | grep FOUND >> $ClamLogFile
  Line 862:  xpstopdf $pathname $newPathname

  Line 1947: clamscan -r $ConvertDir.$file | grep FOUND >> $UserClamLogFile

IMPACT:

  - Process/read unintended files in the same directory
  - Information disclosure if multiple users share directory space
  - ClamAV scans unintended files
  - ImageMagick/FFmpeg processes unintended inputs
  - Potential for crafted image files to trigger ImageMagick vulnerabilities
    on files the attacker couldn't directly reference

SEVERITY: Medium (CVSS ~5.3)
  - Requires file upload capability (available without auth by default)
  - Limited to same-directory file matching
  - No direct code execution, but enables secondary attacks

FIX:

  Option A: Add ? to the blacklist in sanitizeString():
    str_split('|\\~#[](){};:$!#^&%@>*<"\'/`?')

  Option B (recommended): Use escapeshellarg() for all shell variables:
    shell_exec('convert '.escapeshellarg($pathname).' '.escapeshellarg($newPathname));

  Option C (best): Replace shell_exec() with proc_open() + argument arrays:
    $cmd = ['convert', '-background', 'none', $pathname, $newPathname];
    $proc = proc_open($cmd, $descriptorspec, $pipes);
